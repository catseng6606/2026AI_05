Web Security 101

什麼是 XSS (Cross-Site Scripting)？

跨網站指令碼（XSS）是一種網頁安全漏洞。當網頁應用程式在未經適當過濾、編碼或驗證的情況下，就將使用者輸入的內容直接輸出到 HTML 頁面中，攻擊者就可以藉此注入**惡意 JavaScript 指令碼**。

當其他無辜的使用者瀏覽受害網頁時，瀏覽器會誤以為這些惡意指令碼是網站本身的一部分並加以執行。這能讓攻擊者竊取敏感資料（如 Session Cookies）、偽造使用者操作、進行網路釣魚或網頁置換。

💾

Stored XSS (儲存型)

惡意代碼被永久儲存在伺服器的資料庫或檔案中。每當有使用者請求該資料時，惡意代碼就會被載入並執行。危害範圍最廣！

Reflected XSS (反射型)

DOM-based XSS (DOM型)

完全發生在瀏覽器的 JavaScript 處理。代碼從不安全的 Source（如 location.hash）讀出，並未經轉義寫入不安全的 Sink（如 innerHTML）。

🛡️ XSS 防禦的核心心法

✔
HTML 實體編碼 (HTML Entity Encoding)

將特殊字元如 < 轉為 &lt;，讓瀏覽器將其視為純文字而非程式碼標籤。

✔
使用安全 API (Use Safe APIs)

在操作 DOM 時，優先使用 textContent 替代 innerHTML，避免動態解析 HTML。

✔
內容安全政策 (Content Security Policy, CSP)

設定 HTTP 標頭限制瀏覽器僅能執行受信任來源的指令碼，甚至禁止行內指令碼（Inline Scripts）。

✔
HTTPOnly Cookies

為敏感 Cookie 加上 HttpOnly 屬性，阻止 JavaScript 透過 document.cookie 存取，保護會話安全。

危險等級：高

💾 Stored XSS 儲存型

攻擊者將惡意代碼（Payload）輸入到受害者會瀏覽的頁面輸入欄（如留言板、使用者檔案、討論區）。這些代碼會被寫入**伺服器端資料庫**。當其他使用者開啟該網頁，瀏覽器向資料庫請求此內容時，惡意代碼便在無預警下自動執行。

🧪 常用攻擊 Payload 範例 (點擊快速填入)

🛠️ 原始碼安全對比

❌ 易受攻擊程式碼 (Vulnerable) 
// 直接將輸入轉成 HTML 節點插入 DOM
container.innerHTML = `<div>${comment.text}</div>`;
✅ 安全防禦程式碼 (Secured) 
// 1. 使用 textContent 來避免 HTML 解析
const div = document.createElement('div');
div.textContent = comment.text;

// 2. 或手動進行 HTML 實體轉義
function escapeHTML(str) {
  return str.replace(/[<>&"']/g, m => ({
    '<': '&lt;', '>': '&gt;', '&': '&amp;',
    '"': '&quot;', "'": '&#x27;'
  })[m]);
}

🔍 Reflected XSS 反射型

當使用者點擊惡意 URL（例如來自惡意郵件或即時通訊的網址），其參數中夾帶的惡意代碼會隨著 HTTP 請求發送到受害網站的伺服器。伺服器未對參數做適當轉義，便直接在回應的 HTML 網頁中將其「反射」輸出回瀏覽器，進而執行程式。

🧪 常用攻擊 Payload 範例

🛠️ 原始碼安全對比

❌ 易受攻擊程式碼 (Vulnerable) 
// 伺服器直接將 URL 的搜尋參數渲染回 HTML 頁面上
const query = new URLSearchParams(window.location.search).get('q');
resultContainer.innerHTML = `<h2>您搜尋的是: ${query}</h2>`;
✅ 安全防禦程式碼 (Secured) 
// 使用 DOM 內建的安全性防禦方法：textContent
const query = new URLSearchParams(window.location.search).get('q');
const title = document.createElement('h2');
title.textContent = `您搜尋的是: ${query}`;
resultContainer.appendChild(title);

🌳 DOM-based XSS DOM型

與傳統 XSS 不同，DOM-based XSS 的漏洞不涉及伺服器端（在後端的 HTTP 回應中看不到惡意字串）。它的發生是因為前端網頁的 JavaScript 在執行時，以不安全的方式（例如 innerHTML 或 document.write）處理了來自瀏覽器的不安全來源（如 location.hash 或 location.search）。

🧪 常用攻擊 Payload 範例

🛠️ 原始碼安全對比

❌ 易受攻擊程式碼 (Vulnerable) 
// 不安全：直接將 window.location.hash 接在 HTML 字串中寫入
const hashContent = decodeURIComponent(window.location.hash.slice(1));
outputDiv.innerHTML = "你的自訂佈景為: " + hashContent;
✅ 安全防禦程式碼 (Secured) 
// 方案 A：使用 textContent 保障不被解讀為 HTML
const hashContent = decodeURIComponent(window.location.hash.slice(1));
outputDiv.textContent = "你的自訂佈景為: " + hashContent;

// 方案 B：進行白名單驗證（例如只允許特定顏色字串）
const validThemes = ['dark', 'light', 'cyber'];
if (validThemes.includes(hashContent)) {
    outputDiv.textContent = "您的佈景為: " + hashContent;
}
