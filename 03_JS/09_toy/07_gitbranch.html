🌿 學生分支與備份樹狀結構

本機制流程如下：

  1. 自主幹分出 student/date1，在舊架構 (C1) 下提交第一階段邏輯。
  2. 老師重構主幹，提交 C3: 老師最新架構。
  3. 學生從最新主幹 (C3) 分出 student/date2，繼承最新架構，並在其中完成第二階段重構與修正。
  4. 最後切回 main，保持 main 的乾淨，利用 Gemini CLI 智慧提取這兩個備份分支的精華進行無痕覆蓋整合。

🤖 為什麼 Date 2 必須從新 main 出發？

這樣做能確保學生在進行進階開發時，程式碼**已經套用了最新發布的系統依賴、通訊介面與安全機制**。最後透過 Gemini CLI 整合時，AI 只需提取學生在 `student/date1` 寫過的功能，並比對 `student/date2` 的最新成果，無痛合併，完全省去手工解 Merge 衝突的時間與風險。

📋 讓 AI 來教學生下 Git 指令 的提示詞

請複製下方的提示詞並貼給 Gemini CLI，AI 將會為學生產出建立 `student/date1`、取得最新 `main` 並在此基礎上建立 `student/date2` 隨後返回主幹的標準化 Git 操作指令： 

你是一位嚴謹的軟體工程學教授。今天我們要教導學生『如何透過建立獨立的分支（Date 1 與 Date 2）保留不同開發階段的原始碼，然後回到 main 分支，以便利用 Gemini CLI 進行無衝突的代碼提取與整合』。

請為學生撰寫一份極度清晰、步驟分明的教學指引，包含具體的 Git 指令：

1. **第一階段：自初始主幹建立 Date 1 備份分支**
   - 說明如何自當前的基礎開發狀態建立並切換至新分支 `student/date1`。
   - 說明如何將程式碼加入暫存並進行 Commit 提交 (C2)。
2. **第二階段：拉取老師最新 main，並分支出 Date 2**
   - 說明如何切換回 `main` 分支並執行 `git pull` 取得老師最新的主幹代碼 (C3)。
   - **核心重點**：指導學生如何「以此最新 main 狀態為起點」，分支出 `student/date2` (C4)。
   - 說明在 Date 2 中繼承了最新架構，並提交完成進階開發與修正。
3. **第三階段：回到 main 分支準備整合**
   - 指導學生如何安全地切換回到 `main` 主幹。
4. **最後：Gemini CLI 智慧提取命令**
   - 提供一份 Shell 指令範例，說明回到 main 分支後，如何下達 `git show student/date1:路徑` 與 `git show student/date2:路徑` 的提取操作，完全不執行 `git merge`。

輸出請結構分明，程式碼區塊務必加上註釋，方便學生直接理解與在本機 Terminal 複製執行。
